AWS Account Migration

Problem: Multiple production solutions shared AWS accounts, creating security and billing challenges.

Approach: Terraform-based landing zones, SCP policies, phased workload migration with rollback plans.

Result: Isolated accounts per product line, improved cost allocation, and stronger security boundaries.

Terraform Module Best Practices

Design modules with a single responsibility — one module per logical resource group (VPC, EKS cluster, RDS instance). Use consistent input variable naming and output contracts so consuming teams know exactly what they get.

Store state remotely in S3 with DynamoDB locking. Use workspaces or separate state files per environment rather than duplicating code. Tag all resources with environment, owner, and cost center for accountability.

Pin provider versions and run terraform plan in CI on every pull request before merge.

Ansible Role Design Patterns

Structure roles with defaults, vars, tasks, handlers, and templates clearly separated. Document every variable in README.md with type, default, and example values.

Use role dependencies sparingly — prefer composition in playbooks. Test roles with Molecule against multiple OS targets in CI. Version collections semantically and publish to a private Galaxy server for team consumption.

GitHub Actions for Infrastructure

Use OIDC federation to assume AWS IAM roles — never store long-lived credentials in secrets. Split workflows into plan (on PR) and apply (on merge to main) with environment protection rules requiring approval for production.

Cache Terraform providers between runs. Upload plan artifacts and require review before apply. Use reusable workflows for DRY pipeline definitions across repositories.
